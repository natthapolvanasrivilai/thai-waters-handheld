# Rev F circuit verification

**Engineering release status: open.** The ngspice 33 executable ran 42 standalone circuit decks across 14 circuit families. The run yielded 55 measurements, including 33 inside their stated screening bounds, 11 outside and 11 requiring characterization. Several runs deliberately inject faults or stress assumptions. Counts describe simulated conditions and cannot predict a manufacturing yield.

**Cadence PSpice execution is pending.** Each ASCII circuit uses ordinary SPICE elements, .TRAN and .PRINT. The CC/CV surrogate also uses the PSpice VALUE/ABS behavioral current source. The decks target PSpice A/D and execute in ngspice. No available installation or license supplied native Cadence results. The ngspice run provides interface and sensitivity evidence. Vendor PMIC control loops, the class-D power stage and haptic ROM are represented at their electrical boundaries. Their internal functionality requires physical board tests or released vendor models.

## Evidence and reproduction

- [All scalar results](results.csv) lists numerical readings, units, acceptable bounds and status. [Structured results](results.json) includes a file hash and model description for every circuit. [Raw solver printouts](raw-ngspice.zip) retain time and node values for every case. [Case definitions](cases.json) contain measurement windows and conversions.
- [Evidence check](validation.json) confirms 42 deck hashes and raw log CRCs, and compares five representative solutions with independently calculated RC, Ohm-law and sine-power reference values. Run `python check_evidence.py` after rebuilding.
- [Source register](sources.json) maps every case to vendor documents, firmware or BOM. [Bench matrix](bench-matrix.csv) identifies fixtures, acceptance evidence and issues which require an actual assembly. Use the board revision marked on the part.
- To reproduce the delivered run with Python 3.10 or later, execute the following from this directory. The runner needs the ngspice executable and its normal runtime libraries. It writes the results and compressed raw logs only after all cases return numerical data.

~~~text
python run.py --engine /path/to/ngspice --engine-version 33
~~~

The delivered decks are standalone. After a reviewed change to the assumptions, run `python make_decks.py` to regenerate them. Audit the resulting circuit and measurement definition, record the updated solver version and archive the previous result set before a production release. The first line is a SPICE title. A Unicode editor should preserve the plain ASCII decks.

**Native PSpice replay.** On a licensed Cadence workstation, start PSpice A/D and use **File → Open Simulation** on each .cir, then run. Archive the .out files, actual Cadence release/build and the .cir hash from the same run. Inspect solver warnings. Export the printed traces if needed. Use `compare_pspice.py` on those native outputs. Run `python compare_pspice.py native-output native-comparison.csv` after exporting the 42 matching .out files. Use the exact distributed deck bytes on the Cadence workstation. The script implements the same measurement windows and thresholds as ngspice, records per-output hashes, flags boundary or 2% scalar disagreement, and exits with a nonzero code if any native run is missing. A matching screen alone cannot close hardware qualification. See [Cadence guidance](https://community.cadence.com/cadence_technology_forums/pcb-design/f/pcb-design/23747/modelling_photovoltaic_systems_using_pspice/1315332).

## Interpretation by circuit

| Circuit | Result and design consequence |
|---|---|
| Shared GPIO8 SDA / GPIO7 SCL, 400 kHz | The encoder-only 10 kΩ scenario gives 847 ns at 100 pF. Adding a second 10 kΩ gives 424 ns. With an extra 4.7 kΩ path the result is 205 ns at 100 pF, but 411 ns at 200 pF. At 820 Ω the static demand is 3.54 mA at 0.4 V. Measure the real parallel pull-ups, powered logic levels, waveform and installed harness capacitance in both BOM variants. The V2 camera R9/R10 are marked 4.7K/NC. These cases do not prescribe an extra fitted resistor. The RC limit implies ~3.54 kΩ maximum for 100 pF at 300 ns. |
| USB-C power and connect | A simulated 4.75 V host with a 0.65 Ω loop and 650 mA load leaves ~4.33 V at the PMIC while exceeding the assumed configured legacy-port current budget. The 330 mA unconfigured case exceeds a 100 mA default USB 2.0 host budget. Host authorization, PMIC input current limit, charge priority, suspend draw and cold boot need current traces. Verify both 5.1 kΩ CC terminations R24/R26 on V2. A deliberately open CC pin reads ~5 V and explains one-orientation attach failure. Do not infer a 1.5 A contract merely from the USB-C connector. |
| Battery and J7 | The aged 3.40 V OCV, 0.55 Ω total pack/loom and 720 mA pulse scenario reaches 3.003 V at J7. The 3.30 V project screening target reserves upstream headroom for the 3.3 V rail. It is neither a programmed cutoff nor a cell-safety threshold. Measure pack DC resistance with the actual protected cell, adapter and splices, then correlate J7 with the CPU rail and shutdown behavior. |
| 3.3 V output | UP1 LX1/L5 feeds VCC3V3. C81/C82/C83 are nominally 22 µF/1 µF/100 nF. Other board decouplers can contribute. The 28 µF effective, 300 mA transient case falls to 3.219 V. Assuming 12 µF and a 12 µs response delay on a 350 mA step gives 2.836 V. These charge-deficit bounds parameterize unmeasured effective capacitance, ESR and recovery latency. They cannot establish loop phase margin. Scope the MCU pin during simultaneous radio transmit, LCD, audio and haptics on a low battery. |
| Charging and temperature | Firmware sets 4.2 V and 300 mA and checks the register values. Ideal CC/CV examples give 300/75/5 mA for the three test cell voltages. The threshold is the selected pack supplier's 500 mA ceiling. Numerical agreement with an ideal controller says nothing about independent charger tolerance, charger POR before firmware, termination or faulty packs. The switch-charger reference uses a buck path. Identify the actual PMIC option and L6/R25/R27/R28 population. Hypothetical 0.22 W × 55 K/W at 25 °C and 0.55 W × 85 K/W at 40 °C yield 37.1 and 86.75 °C at the modeled hot node. Power, thermal resistance, time constant and air temperature are assumptions. Neither output is a measured cell, surface or junction temperature. |
| Cell temperature sensing | J7 carries two battery wires. The V2 sheet shows board component R29 at TS; confirm that actual lots carry a thermistor and that Reg 0x50 enables charge qualification. At assumed 50 µA the 25 °C, 10 kΩ equivalent gives 0.500 V; the 45 °C equivalent gives 0.246 V. The installed board sensor can stay cool while the cell is hot. Characterize/refine cell-coupled temperature protection and voltage limits with the battery supplier and evaluate off-state USB charging before production. |
| Raw power key | On V2, R38 is between PWRON and raw K3; R37 then connects K3 to the transistor gate, which has R65 pull-up. SW1 parallels the actual contacts. A 10 kΩ contamination fault leaves 0.781 V at the PMIC under an assumed 50 kΩ internal pull-up and exceeds our 0.33 V low margin. The stock V1 schematic moves the R37 connection and lacks the same R65 branch. A received V1 unit requires the correct topology and a new run. Check both physical buttons, firmware one-second start/four-second off, pocket load, ESD and boot on battery with no active CPU. |
| Reset and touch | R14/C19 and R11/C8 nominal 10 kΩ / 100 nF generate a ~1.39 ms edge to 75%. This is a measurement convention. Scope rail-valid, CHIP_PU release and LCD reset after any PMIC ramp; confirm successful touch enumeration and all nine touch targets in the closed case. |
| ES8311 → NS4150B → J9 | R40/R42 bring differential outputs to J9. R55 ties the PA supply to VSYS on V2. A 1.4 V peak differential sine across 6 Ω dissipates 0.163 W. At 3.3 V peak it dissipates 0.907 W; at an assumed 3.9 V into 5.4 Ω it reaches 1.408 W. A rating of 1 W at 6 Ω corresponds to 2.45 V RMS. Verify the actual speaker and frequency-dependent impedance. Measure differential RMS, clipping and the combined music/click/bite crest case using two matched differential inputs or an appropriate differential probe. The firmware codec setting of 65 does not establish an acoustic or electrical limit. |
| Coin ERM and DRV2605L | A simple 3 V running-equivalent load gives 60 mA, matching the cited 3 V/60 mA catalogue point by construction. Assumed 22 Ω and 15 Ω startup envelopes give 136 mA and 200 mA. DCR, inductance, back EMF, ROM effects, active braking, free rotor startup and rail interaction require actual captures. Check Reg 0x17, all configured levels, pulsed duty, temperature and false reel counts with haptics running. Electrical parameters here do not establish a tactile experience. |
| LCD backlight | V2 R3 = 6.8 Ω, R4 = 0 Ω and T1 = AO3400. The nominal assumed 2.95 V LED drop and 3.3 V rail yield ~51 mA. The 2.8 V / 3.4 V corner gives ~92 mA. Characterize the received panel, display brightness firmware and backlight current; the LCD FPC rating and string topology must be confirmed before assigning a safe PWM envelope. |
| USB D+/D− | V2 series R18/R19 = 22 Ω. The lossless full-speed line fixtures use 23 Ω assumed driver resistance, 45 Ω per leg, 5 ns cable delay, and aggregate 10/100 pF loads. Record edge times and high-level voltage in results.csv. An assembled product needs enumeration, actual bus eye, common mode, contact orientation, ESD and suspend testing. Full-speed eye compliance requires a compliant fixture and physical waveforms. |

## Evidence boundary for the engineering release

Electrical integration is still open until the matrix has serial-numbered results. Maintain a configuration record for the board revision, PMIC stuffing, battery lot, display/speaker subassembly, driver variant, printed case, harness lengths and firmware identifier. Record actual readback of charge target, charge current, VBUS current limit, TS configuration and off-state behavior. The USB input specification and battery charge envelope require procurement-controlled limits. The modeled radio/PA/motor loads need measured duty profiles before estimating play time or thermal margins.

RF antenna clearance/efficiency, ESD/EMC immunity and emissions, connector and plastic wear, battery abuse/safety, tactile and acoustic output, final CPU display/touch timings, drop testing, BLE/Wi-Fi coexistence, RTC holdover, power-loss-safe updates and production fixture coverage all need other verification. Use the matrix as a correlation and re-test record after changing board lot, harness, enclosure, radio settings, charge profile, motor or speaker.

Source documents and exact case assumptions are indexed in [sources.json](sources.json) and [cases.json](cases.json).
### Charger firmware review

`Board.cpp` programs and reads back the charge voltage/current after the CPU starts. In the reviewed build, `powerOK` feeds the boot log and update-health check. No product code was found that sets and reads back the USB input-current limit, configures TS fault action, or forces charging off when charge-profile verification fails. Verify actual PMIC reset/EFUSE behavior with USB applied and the processor held off. Before design release, select hardware defaults and charger supervision that keep the received pack within its vendor envelope in each power state. Close EV-02 through EV-04 with measured evidence.
